# 简历与演示材料

## 可用于简历的项目描述

**知径 · 个人知识导航 Agent｜Python、FastAPI、SQLite FTS5、JavaScript**

- 独立实现可本地运行的个人知识库，支持纯文本/Markdown 编辑、事务内索引更新、中文双字词与 BM25 检索，以及带版本和正文 SHA256 的原文引用。
- 实现由模型选择 `search`、`read`、`final` 的有限步检索循环，支持依据搜索结果改写关键词；默认最多 6 步，并展示每次动作与真实工具结果摘要。
- 在搜索、读取和最终回答三个环节固定文档范围，拒绝伪造/未读/过期片段及无来源支持的入口；超限和上游失败均返回明确错误，空引用则弃答。
- 完成 44 项本地自动化测试，覆盖真实 SQLite 检索、CRUD/并发版本冲突、多轮模型动作、范围逃逸、伪造来源、入口越权、最大步数与上游异常；配置 Windows/Linux × Python 3.11/3.12 CI。

以上测试数量来自 2026-11-06 本地运行记录。模型动作由 `httpx.MockTransport` 确定性驱动，真实检索和片段读取使用 SQLite；未将其描述为已接通真实模型或模型效果评测。

## 三分钟演示

1. 默认本地模式查询“每周复盘”，指出原文、版本、SHA256 和可打开的工作入口。
2. 只选择复盘文档再查 `RAG`，展示未找到，说明范围由服务端 SQL 强制执行。
3. 新建独有关键词的笔记，查询、修改、再次查询，展示数据库与索引同步。
4. 打开自动化测试中的 `test_agent_rewrites_search_after_zero_hits`：模型脚本先得到零命中，再改写关键词，执行 read 和 final；工具查询确实运行。
5. 展示 `test_max_steps_stops_model_without_fake_success` 与未读引用测试，说明何时停止以及为何拒绝结果。
6. 若已配置真实模型服务，可现场运行 Agent 检索并展开轨迹；若未配置，演示明确失败并说明当前验收边界。

## 面试时值得解释的选择

- **为什么有两种模式？** 本地模式提供可离线核对的基础检索，Agent 模式用模型控制检索步骤。前者不宣称具备模型规划能力。
- **为什么搜索后还要读取？** 搜索只返回短预览，read 读取当前原文；最终引用只接受已读片段，避免把候选命中直接视作完整证据。
- **为什么反复检查范围？** 提示词不构成数据访问约束。SQL 搜索与读取都使用原始请求范围，最终引用再核对一遍。
- **是否保证答案正确？** 保证引用真实、当前且在范围内，不保证模型对原文的语义解释完全正确，故始终展示原文。
- **如何控制成本与终止？** 默认 6 步、硬上限 12 步，每次请求有超时；没有无限重试、静默回退或假成功。
- **哪些能力尚未完成？** 多用户鉴权、PDF/Word 解析、语义向量召回、真实模型效果基准与生产规模性能测量。

## 量化与来源边界

可陈述的数字：44 项本地测试、3 类工具动作、默认 6 步/最多 12 步、每次最多 6 个搜索片段、每片段最多 500 字符、4 份合成演示文档和 3 个本地入口。

不要将演示数据量描述为真实用户规模，不写没有测量过的准确率提升、响应时延、成本节省、生产吞吐量或日活数据。CI 矩阵是配置事实，远程通过情况以实际 Actions 结果为准。

通用来源/入口边界适配自已有辅助搜索设计，仓库与来源 revision 已记录；`navigator/protocol.py` 保留 Mulan PSL v2，其余新增代码使用 MIT。项目没有携带原平台数据、认证、私有依赖或 Git 历史，详见 `THIRD_PARTY_NOTICES.md`。
